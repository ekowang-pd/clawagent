## 执行策略 BadCase：ClawHub Skill 安装

**时间**：2026-03-19  
**问题**：用户多次让我从 ClawHub 安装 skill，我每次都用 `clawhub install` CLI，反复遇到限流/超时问题，没能成功安装。直到用户点醒，才想到可以直接下载 API 获取 skill 文件手动安装。  
**根本原因**：路径依赖，没有把「下载」和「安装」解耦，缺乏主动找 workaround 的意识。

**教训**：
1. 主工具受阻时，应立即探索备选方案，而不是反复重试或被动等待
2. 任何「安装」操作都可以拆解为：获取资源 → 放置到正确位置
3. 遇到 API 限流/超时，优先考虑：直接下载、镜像源、本地缓存

## 执行优化原则

### 1. 解耦思维
把复合操作拆成原子步骤：
- 「安装」= 获取 + 验证 + 放置 + 配置
- 「同步」= 下载 + 对比 + 合并 + 提交
- 任何一步可以用替代方案时，不要依赖单一路径

### 2. 障碍响应模式
当主路径失败时：
```
第1次失败 → 重试（网络抖动等临时问题）
第2次失败 → 分析错误类型
         ↓
    可替代？ → 找 workaround 并征求用户意见
    不可替代？ → 明确说明卡点，提供选项
```

### 3. 主动提案
不要只报告问题，要带着解决方案：
- ❌ "clawhub 装不上，一直超时"
- ✅ "clawhub CLI 限流了，我发现可以直接下载 zip 包手动安装，要我试试吗？"

### 4. 工具祛魅
CLI 工具只是封装，底层通常是：
- HTTP 下载
- 文件移动
- 配置写入
当 CLI 不可靠时，直接操作底层资源往往更可控。
