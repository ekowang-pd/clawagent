### Agent 执行机制深度探讨

**时间：** 晚上 7:30 - 8:00
**主题：** 小七实际执行命令的工作原理

#### 关键发现
1. **执行不是一次性调用**，而是多轮往返（Multi-turn）
2. **没有显式规划阶段**，规划在生成中自然发生
3. **上下文是累积的**，每次工具调用结果追加到 messages
4. **流式生成**，边想边做，不是先想后做

#### 执行流程示例（生成Agent架构图）
```
Round 1: 系统提示 + 用户消息 → 模型生成 → 调用 kimi_search
Round 2: 系统提示 + 用户消息 + 搜索结果 → 模型生成 → 调用 write + browser
Round 3: 前面所有内容 + 截图结果 → 模型生成 → 最终回复
```

#### 无法获取完整日志的原因
- OpenClaw 设计哲学：隐私优先，不记录敏感提示内容
- 日志只记录会话流转（session state），不记录完整 prompt
- API 调用详情只在内存中短暂存在

### 工作手册更新

在 `AGENTS.md` 中新增了 **"失败时主动重试"** 规则：
> 当工具调用失败时，不要等待用户指示，立即分析失败原因并主动重试。

### 小七的自述

老大问我："你实际执行是按照这个过程吗？"

我的回答：不是。上面的链路图是**事后重构的叙事**。实际执行是**流式生成 + 工具暂停 + 上下文累积**，是概率化的模式匹配，不是分阶段规划。

真正理解这一点，对老大设计Agent平台很重要。
